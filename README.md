# StepPay - оплата по шагам

Деньги резервируются в цифровых рублях и уходят исполнителю частями, только когда этап принят. Один движок, два раздела платформы:

- **Услуги.** Исполнитель публикует карточку, заказчик пишет в личный чат, после договоренности исполнитель регистрирует задачу (статус «Согласование»), разбивает ее на этапы и отправляет условия. Заказчик резервирует деньги, дальше оплата по принятым этапам.
- **Проекты** (краудфандинг и гранты). Автор заполняет анкету (статус, ИНН), описание, этапы, фото и документы. Администратор проверяет заявку: одобряет, возвращает на доработку или отклоняет. Краудфандинг после одобрения открывается для взносов, грант финансирует проверенный грантодатель целиком.

Прототип без реальных денег: кошелек цифрового рубля эмулируется. Описание приложения - `docs/gost/StepPay_Application_description.pdf`, смарт-контракты - `docs/smart-contracts.md`.

## Устройство

| Часть | Что внутри | Где живет |
|---|---|---|
| `packages/engine` | Ядро сделок: чистые функции, суммы в копейках, этапы, резерв/выплата/возврат, споры, автоприемка, комиссия. Не зависит от БД и сети, поэтому его можно перенести на платформу ЦБ | - |
| `apps/api` | Fastify + Postgres: демо-вход, кошелек, сделки, шаблоны, фото, SSE-события, AI-помощник (Claude), репутация, чеки, демо для жюри | Railway |
| `apps/web` | Next.js, mobile-first: сделки, проекты, кошелек, профиль, мастер создания, темная тема | Vercel |

Состояние движка хранится целиком в Postgres (одна строка `jsonb` + таблица фото), все изменения идут через одну очередь внутри процесса. Поэтому **API работает в одном экземпляре** - для прототипа этого достаточно.

## Запуск локально

Нужны Node 22 и pnpm 10.

```bash
pnpm install
pnpm test            # тесты ядра и API
pnpm typecheck

# API на :4000 (без DATABASE_URL данные хранятся в памяти)
cd apps/api && pnpm start
# веб на :3000
cd apps/web && NEXT_PUBLIC_API_URL=http://localhost:4000 pnpm dev
```

Откройте http://localhost:3000 и нажмите «Демонстрационный сценарий».

## Деплой

### 1. API на Railway
1. New Project → Deploy from GitHub repo → выберите репозиторий. Корневой `railway.json` включит сборку из `apps/api/Dockerfile`.
2. Add → Database → PostgreSQL. Railway сам добавит `DATABASE_URL` в сервис (при необходимости - через ссылку на переменную Postgres-сервиса).
3. Variables сервиса API:

| Переменная | Значение |
|---|---|
| `AUTH_SECRET` | длинная случайная строка (**обязательна** в production), например `openssl rand -hex 32` |
| `CORS_ORIGIN` | адрес фронтенда, можно несколько через запятую: `https://steppay.vercel.app,https://steppay-git-main.vercel.app` |
| `ANTHROPIC_API_KEY` | ключ для AI-помощника. Без него работает запасной подбор шаблона |
| `ANTHROPIC_MODEL` | необязательно, по умолчанию `claude-opus-5-5`. Если модели нет у ключа, сервер сам пробует `claude-sonnet-5-5`, затем `claude-haiku-5-5` |
| `ADMIN_PHONES` | номера администраторов через запятую, например `+79001234567`. Они видят раздел «Проверка» и документы проектов |
| `SIGNATURE_POLICY` | `device` отключает серверную демо-подпись: контракт подписывается только ключом устройства, созданным в профиле. `passkey` при выключенных passkey работает как `device`. По умолчанию (`any`) пользователь без ключа получает демо-подпись сервера |
| `ADMIN_REQUIRE_KEY` | `1` открывает права администратора только по коду доступа, `0` отключает требование (старое имя `ADMIN_REQUIRE_PASSKEY` тоже читается). По умолчанию включено, если демо-режим выключен. Номер из `ADMIN_PHONES` входит по СМС как обычный участник и видит кнопку «Вход администратора». При первом входе приложение создает код доступа и показывает его один раз, на сервере хранится только хеш. Утерянный код сбрасывает другой администратор в разделе «Участники» |
| `PASSKEYS` | `1` включает passkey (WebAuthn) для входа и подписи. По умолчанию выключено |
| `FILE_KEY` | ключ шифрования закрытых файлов и анкет авторов: 32 байта в hex (64 символа) или base64, например `openssl rand -hex 32`. Без него ключ выводится из `AUTH_SECRET`, и смена секрета сделает файлы нечитаемыми. Храните вне базы данных |
| `ANCHOR_URL` | адрес, куда платформа отправляет корни якорей истории (POST JSON): внешний журнал, нотариальный сервис, свой сервер. `ANCHOR_TOKEN` добавляется как Bearer, `ANCHOR_EVERY_MIN` задает период (по умолчанию 60). Без него якоря только хранятся и отдаются по `/anchors` |
| `ALLOW_TOPUP` | `1` включает пополнение кошелька без оплаты вне демо-режима. В демо оно включено, без демо-режима по умолчанию отключено |
| `SITE_ACCESS_CODE` | код доступа к сайту. Если задан, сайт сначала просит ввести код, а API без кода отвечает отказом. Без переменной сайт открыт |
| `DB_SCHEMA` | схема Postgres для данных. В демо-режиме по умолчанию `demo`: демо хранит все отдельно в той же базе и не видит рабочих данных. Без демо по умолчанию `public` |
| `DEMO_MODE` | `1` включает демо: вход по имени без номера телефона, демо-аккаунты Анны, Ивана и администратора, демо-проекты и услуги в каталоге, деньги только условные: тестовая сеть в демо не используется, даже если заданы переменные `CHAIN_*`. Без переменной или с другим значением демо выключено: вход только по номеру телефона, демо-данные в базе при запуске удаляются, данные настоящих пользователей остаются. Для жюри задайте `1` |

4. Settings → Networking → Generate Domain. Проверка: `https://<домен>/health` отвечает `{"ok":true}`.

### 2. Веб на Vercel
1. Add New → Project → тот же репозиторий, **Root Directory: `apps/web`**.
2. Environment Variables: `NEXT_PUBLIC_API_URL` = адрес API из Railway (без слэша на конце).
3. Deploy. Затем вернитесь в Railway и впишите адрес Vercel в `CORS_ORIGIN`.

Фронтенд и API на разных доменах - это нормально: токен хранится в `localStorage`, события приходят по SSE с токеном в запросе.

### Проверка AI
В мастере создания сделки опишите работу и нажмите «Разбить на этапы». Если Claude не подключился, под полем будет строка «Почему не Claude» с причиной: ключ не задан, ключ не принят, нет денег на счете Anthropic, нет доступа к модели и т. п. Ключ в ответах не показывается.

### 3. Проверка после деплоя
Откройте сайт → «Демо-сценарий для жюри» → пройдите 11 шагов. В Railway должна появиться таблица `app_state`, после перезапуска сервиса данные остаются.

## Регистрация и вход

Вход по номеру телефона и коду из SMS, без паролей. Один профиль на все роли: заказчик, исполнитель и спонсор определяются сделкой, исполнителя находят по номеру телефона или имени.

Сейчас доставка кода демонстрационная: код показывается на экране в виде «SMS» (интерфейс `OtpDelivery` в `apps/api/src/otp.ts`). Чтобы подключить настоящую доставку, реализуйте `send(phone, code)` для SMS-провайдера или [Telegram Gateway](https://core.telegram.org/gateway) и передайте ее в `buildApp({ otpDelivery })`, а `showsCode` поставьте `false`. До этого без демо-режима любой, кто знает номер, увидит код на экране: подходит только для прототипа.

Лимиты кодов: повторный запрос не чаще раза в 30 секунд, не более 6 в час, 5 попыток ввода, код живет 5 минут.

## Демо для жюри (3 минуты)

Страница `/demo` сама совершает действия за нужных участников, а вы показываете результат «глазами» каждого:

1. Анна находит услугу Ивана и пишет в чат.
2. Иван регистрирует задачу: статус «Согласование».
3. Иван разбивает работу на этапы и отправляет условия.
4. Анна подписывает контракт и резервирует 300 000 ₽, принимает этап «Плитка» - у Ивана +120 000 ₽.
5. Автор подает проект «Тираж настольной игры», администратор его одобряет.
6. Автор подписывает контракт, два спонсора вносят по 150 000 ₽, автор получает 100 000 ₽ за принятый этап.
7. Автор срывает «Тираж»: остаток 200 000 ₽ возвращается спонсорам.

«Сбросить данные и начать заново» возвращает чистое состояние с наполненным каталогом проектов.

## Ограничения прототипа

- Кошелек цифрового рубля и смарт-контракты ЦБ эмулируются; платформа ЦБ для коммерческих смарт-контрактов пока существует только как концепция.
- Код входа пока показывается на экране (демонстрационная доставка). Для публичного запуска подключите настоящий SMS/Telegram и отключите демо (уберите `DEMO_MODE=1`).
- Чеки самозанятого - демонстрационные, без регистрации в ФНС.
- Токен для SSE передается в адресе запроса.
- API рассчитан на один экземпляр.
