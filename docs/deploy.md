# StepPay: запуск и проверка

Пошаговый порядок для Railway (API и база) и Vercel (сайт). Подробности по переменным есть в `README.md`, здесь порядок действий и проверки после запуска.

## 1. Что проверено до запуска

На локальном запуске в режиме, близком к боевому (`NODE_ENV=production`, `DEMO_MODE=off`, строгий CORS, production-сборка сайта): все тесты проходят, скрипт `scripts/smoke.mjs` дает 0 провалов. Не проверено из среды разработки: ваш Railway и Vercel (нет доступа), настоящие сервисы ФНС, публичная сеть Ethereum, passkey на реальном телефоне.

## 2. Railway (API и база)

1. New Project, Deploy from GitHub repo, ветка с кодом. Корневой `railway.json` включит сборку `apps/api/Dockerfile`.
2. Add, Database, PostgreSQL: `DATABASE_URL` появится сам.
3. Переменные сервиса API (готовый блок со свежими секретами: `node scripts/gen-env.mjs --api https://API --web https://САЙТ --admin +79001234567`):

| Переменная | Обязательна | Значение |
|---|---|---|
| `NODE_ENV` | да | `production` (включает HSTS и строгий CORS) |
| `AUTH_SECRET` | да | `openssl rand -hex 32`, смена выбрасывает всех из аккаунтов |
| `FILE_KEY` | да | `openssl rand -hex 32`, ключ шифрования файлов и анкет. Без него ключ выводится из `AUTH_SECRET`. Сохраните отдельно от базы |
| `CORS_ORIGIN` | да | точный адрес сайта: `https://ваш-сайт.vercel.app`. Без него не работают вход и passkey |
| `DEMO_MODE` | нет | для публичного запуска `off`, для показа жюри оставьте включенным |
| `ADMIN_PHONES` | да вне демо | номера администраторов: `+79001234567` |
| `ADMIN_REQUIRE_PASSKEY` | нет | по умолчанию включено вне демо |
| `SIGNATURE_POLICY` | нет | `passkey`, чтобы подписывать контракты только passkey |
| `ANCHOR_URL`, `ANCHOR_TOKEN` | нет | куда отправлять корни якорей, см. раздел 5 |
| `ANTHROPIC_API_KEY` | нет | подбор этапов ИИ, без него работает запасной подбор |

4. Settings, Networking, Generate Domain. Проверка: `https://<домен>/health` отвечает `{"ok":true}`.

## 3. Vercel (сайт)

1. Add New, Project, тот же репозиторий, Root Directory `apps/web`.
2. Переменная `NEXT_PUBLIC_API_URL` равна адресу API из Railway без слэша. Она зашивается при сборке: после смены нужна новая сборка.
3. Deploy. Затем впишите адрес сайта в `CORS_ORIGIN` на Railway и перезапустите API.

Порядок важен: сначала API, потом сайт, потом `CORS_ORIGIN`. Постоянный адрес сайта выбирайте сразу: passkey привязан к домену, при смене адреса их нужно создавать заново. Временные адреса Vercel для проверок не подходят.

## 4. Автоматическая проверка

```
node scripts/smoke.mjs https://<api>.up.railway.app https://<сайт>.vercel.app
```

Она проверяет: заголовки безопасности, CORS (свой сайт пускает, чужой нет), закрытость служебных адресов без входа, поддельный токен, режим демо, выдачу запроса для passkey, якоря. Выход 0 значит провалов нет, предупреждения читайте: например, «демо-режим включен» нормально для показа жюри и ненормально для публичного запуска.

## 5. Ручные проверки

**Администратор и passkey** (выполняют на телефоне и компьютере, по https):
1. Войти по СМС номером из `ADMIN_PHONES`. Должна появиться плашка «Администратору нужен вход по passkey».
2. Профиль, «Добавить passkey», подтвердить отпечатком или лицом.
3. Выйти, на экране входа «Войти с passkey». Раздел «Проверка» должен открыться, плашки быть не должно.
4. Если ошибка «Passkey создан на другом сайте»: `CORS_ORIGIN` не равен адресу сайта. «Passkey привязан к другому домену»: passkey создан на другом адресе, создайте заново.

**Подпись контракта passkey:** создать сделку между двумя аккаунтами, подписать на телефоне. В карточке «Контракт» нажать «Проверить подписи на этом устройстве»: подпись passkey должна пройти.

**Сверка с ФНС** (нужны реальные ИНН): в мастере проекта сохранить анкету с ИНН настоящего самозанятого, затем настоящей организации (с ее названием из ЕГРЮЛ) и ИП. Ожидается метка «Сверено с ФНС». Для заведомо выдуманного, но корректного по контрольным цифрам ИНН ожидается «Расхождение с ФНС». Если везде «ФНС недоступна», пришлите ответ сервиса: формат запросов написан по описанию и не проверялся на живом сервисе. Если исходящие запросы блокирует хостинг, откройте доступ к `statusnpd.nalog.ru` и `egrul.nalog.ru`.

**Якоря и свидетель:** задайте `ANCHOR_URL` (адрес, принимающий POST с JSON), через час после первых сделок `/anchors` покажет якорь с отметкой публикации. На другой машине по расписанию запустите `node apps/api/scripts/witness.mjs https://<api> witness.json`: выход 1 означает, что история переписана.

**Публичная сеть (Sepolia или Base Sepolia):**
```
cd packages/contracts
SEPOLIA_RPC_URL=... DEPLOYER_PRIVATE_KEY=... EXPLORER_URL=https://sepolia.etherscan.io pnpm chain:sepolia
ANCHOR_API=https://<api> SEPOLIA_RPC_URL=... DEPLOYER_PRIVATE_KEY=... pnpm hardhat run scripts/anchor.js --network sepolia
```
Ключ только тестовый, только в переменных окружения. Нужны тестовые монеты на счете (кран сети). После прогона отчет с адресами и транзакциями привязывается к сделке и виден в карточке сделки.

## 6. Откат

- Сайт: в Vercel, Deployments, предыдущая сборка, Promote to Production.
- API: в Railway, Deployments, предыдущий выпуск, Redeploy.
- Данные: состояние хранится в Postgres одной записью на тип данных. Перед обновлением сделайте копию (Railway, Database, Backups или `pg_dump`). Копии, сделанные до включения шифрования, содержат открытые анкеты и файлы: удалите их или храните как секретные.
- Смена `AUTH_SECRET` разлогинит всех, смена `FILE_KEY` или `AUTH_SECRET` без `FILE_KEY` сделает зашифрованные файлы и анкеты нечитаемыми. Не меняйте их без необходимости.

## 7. Частые сбои

| Симптом | Причина |
|---|---|
| Вход и запросы с сайта падают с ошибкой сети | `CORS_ORIGIN` не равен адресу сайта, или `NEXT_PUBLIC_API_URL` указывает не на API |
| Passkey не создается | сайт не по https, нет блокировки экрана на устройстве, `CORS_ORIGIN` неверен |
| Раздел «Проверка» закрыт у администратора | сессия по СМС: добавьте passkey и войдите с ним (или `ADMIN_REQUIRE_PASSKEY=0`) |
| Файлы проектов не открываются после перезапуска | изменился `FILE_KEY` или `AUTH_SECRET` |
| Сверка ФНС везде «недоступна» | хостинг блокирует исходящие запросы или ФНС просит капчу |
| Демо не сбрасывается, чужие данные в каталоге | `DEMO_MODE` не выключен, а база общая |

## 8. Тестовая сеть Ethereum: сделки на контракте

Приложение может повторять действия по сделкам на контракте StepEscrow в Sepolia (или Base Sepolia) с тестовым токеном tRUB. Ядро сделок остается главным: пользователь не ждет сети. Каждое действие (подпись, резерв, сдача, приемка, спор, отмена, срок) уходит в сеть следом, а потом сверяется (статусы этапов, резервы). В сделке появляется карточка «Тестовая сеть» с хешами транзакций и кнопкой «Сверить с контрактом».

Как устроено: у каждого участника есть тестовый кошелек, ключ которого выводится из `CHAIN_WALLET_SEED` и идентификатора пользователя (HKDF), поэтому ключи нигде не хранятся. Транзакции подписывает сервер от имени участника. Газ и токены tRUB выдает счет развертывателя, при первом действии участника. Для настоящих денег такая схема не подходит: там ключи должны быть у владельцев.

### Шаги

1. Создайте новый кошелек для испытаний (например, в MetaMask), скопируйте его приватный ключ. Не используйте кошелек, где есть настоящие деньги.
2. Получите тестовый ETH на этот адрес из крана Sepolia. Нужно около 0.1 ETH: на каждого участника уходит примерно 0.003 ETH, остальное на транзакции.
3. Создайте приложение в Alchemy или Infura, выберите Sepolia, скопируйте адрес узла (HTTPS URL).
4. На компьютере с Node.js 20+ в папке репозитория:
   ```
   pnpm install
   cd packages/contracts
   SEPOLIA_RPC_URL=<адрес узла> DEPLOYER_PRIVATE_KEY=0x<ключ> pnpm deploy:sepolia
   ```
   Скрипт выпустит токен tRUB и контракт StepEscrow и напечатает адреса и переменные. Результат сохранится в `packages/contracts/reports/deployment-11155111.json`.
5. В Railway, сервис API, Variables, добавьте:

| Переменная | Значение |
|---|---|
| `CHAIN_RPC_URL` | адрес узла из шага 3 |
| `CHAIN_ID` | `11155111` (Base Sepolia: `84532`) |
| `CHAIN_ESCROW` | адрес StepEscrow из шага 4 |
| `CHAIN_TOKEN` | адрес токена из шага 4 |
| `CHAIN_DEPLOYER_KEY` | тот же приватный ключ из шага 1 |
| `CHAIN_WALLET_SEED` | `openssl rand -hex 32`, сохраните как секрет: от него зависят адреса кошельков участников |

   Нажмите Deploy. В логе будет строка «Тестовая сеть: Sepolia, контракт 0x...». Проверка: `GET /chain/status` должен вернуть `enabled: true`.
6. Создайте новую сделку и пройдите ее до конца. В сделке откройте «Тестовая сеть»: должны быть хеши транзакций со ссылками на Etherscan. Нажмите «Сверить с контрактом»: ожидается «Совпадает».

### Что нужно знать

- Переносятся сделки, созданные после включения сети. Демо-сделки (`seed-`, `demo-`) не переносятся.
- Токен `TestRub` выпускает кто угодно: это тестовая монета без стоимости, она годится только для испытаний.
- Сроки (автоприемка, срок этапа) на контракте считаются по времени сети. Если ядро уже приняло этап по сроку, а в сети срок еще не вышел, действие повторяется каждые 30 секунд до 20 раз, а потом показывается ошибка. В публичной сети время не ускорить, поэтому для проверки сроков заведите сделку с минимальным сроком или смотрите локальные тесты.
- Если контракт отказал (нет эфира у развертывателя, ошибка узла, расхождение правил), перенос сделки останавливается, в карточке видна причина, приложение продолжает работать. Пополните счет развертывателя и повторите: остановленную сделку нужно разобрать вручную.
- Утечка `CHAIN_DEPLOYER_KEY` опасна только тестовыми монетами, но ключ все равно храните как секрет и не используйте его нигде больше.

### Кошелек в сети и откуда берутся токены

В приложении: Профиль, самая нижняя строка «Тестовая сеть» (видна, только если сеть подключена). Там адрес участника, баланс tRUB и ETH на газ, кнопка «Получить 10 000 ₽ в tRUB» и ссылки на обозреватель.

Токены tRUB не покупаются: у `TestRub` открытая функция `mint`, и платформа (счет `CHAIN_DEPLOYER_KEY`) выпускает их двумя способами:
1. Автоматически перед резервом по сделке: на адрес участника выпускается ровно столько, сколько не хватает для взноса, и разрешается контракту сделок их списать (`prepare` в `apps/api/src/chain.ts`).
2. По кнопке в приложении (`POST /me/chain/faucet`, не чаще раза в 30 секунд, до 10 000 ₽ за раз, и только пока на адресе меньше 50 000 ₽).

Дальше токены двигает только контракт сделок: резерв, выплата исполнителю, возврат. Рубли в кошельке приложения и токены в сети считаются отдельно, деньги между ними не переводятся.
