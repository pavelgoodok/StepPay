# Дорожная карта доработок StepPay

Состав: что сделано, что необходимо до пилота, что нужно для роста. Приоритеты: A, до пилота; B, после запуска пилота; C, для масштаба.

## Сделано

- Хранение: сделки, кошельки и журнал в таблицах, пользователи и данные платформы построчно, сообщения чатов и журнал администраторов отдельными строками.
- Несколько экземпляров API: версия состояния с повтором при конфликте, общие коды входа, события через LISTEN/NOTIFY, фоновые задачи через аренду.
- Интерфейс администратора, заявки на подтверждение данных, отметка «Проверено» в профиле и каталоге.
- Режимы аккаунтов, отзывы и рейтинг, раздел уведомлений, документы для Банка России, презентация и видео.

## A. До пилота

1. Развертывание. Передеплоить Railway и Vercel, проверить миграцию таблиц на копии боевой базы, сделать резервную копию перед выкладкой, настроить регулярные копии базы.
2. Перенос в сеть при нескольких репликах. Вынести ChainMirror в отдельный процесс-лидер (или очередь задач в базе), чтобы запуск нескольких экземпляров не требовал отключения сети. Пока при заданных CHAIN_* работает один экземпляр.
3. Вход администраторов. Включить обязательный passkey (ADMIN_REQUIRE_PASSKEY), проверить вход по passkey на реальных устройствах и доменах (RP ID, origin), добавить второго администратора и порядок восстановления доступа.
4. Подпись контракта. Для рабочего режима задать SIGNATURE_POLICY=passkey или device: серверная подпись (HMAC) остается только для демо.
5. Реальная доставка кодов входа. Подключить SMS или Telegram Gateway вместо демо-доставки, проверить лимиты запросов кода.
6. Пополнение и вывод. Подключить платежный контур (цифровой рубль или эквайринг) вместо демо-пополнения, определить порядок вывода, комиссии, чеки.
7. Сверка с ФНС. Проверить работу сервисов ФНС из окружения Railway (капча, недоступность), описать порядок ручной проверки администратором.
8. Тесты в браузере. Сделано: apps/e2e, 16 сценариев Playwright (регистрация, вход, оплата по шагам, спор, чат и регистрация задачи, отзывы и рейтинг, краудфандинг с голосованием и возвратом остатка, панель администратора, подтверждение данных, мобильная вёрстка), отдельное задание e2e в CI. Далее: сценарий гранта и проверки проекта с возвратом на доработку.
9. Данные письма и документов. Указать в письме в Банк России адресата («Кому»), проверить иллюстративные числа в презентации и резюме, согласовать формулировки с юристом.

## B. После запуска пилота

1. Уведомления. Push и почта для событий сделки, настройка каналов в профиле.
2. Каталог. Фильтр «Только проверенные», сортировка по рейтингу и цене, поиск по описанию.
3. Администратор. Выгрузка операций в CSV, фильтр по периоду, карточка участника с историей сделок, блокировка аккаунта, управление шаблонами.
4. Споры. Напоминания приемщику до истечения срока, оценка работы приемщика участниками, шаблоны решений.
5. Отчетность. Выписка для налогов самозанятых и ИП (чеки НПД), годовые отчеты по сделкам.
6. Мониторинг. Журнал ошибок, показатели задержки и доли отказов, оповещения о расхождении сети и базы (reconcile), проверка целостности журнала и якорей по расписанию.
7. Документация API (OpenAPI), описание ошибок и версий.
8. Доступность. Проверка контраста, управления с клавиатуры, чтения экранным диктором в основных экранах.

## C. Для масштаба

1. Хранилище. Перейти от загрузки всего состояния в память к чтению нужных сделок из базы под блокировкой уровня сделки. Номер записи журнала сделать последовательностью базы. Это снимает последнее ограничение по числу сделок на один экземпляр.
2. Общий счетчик запросов (в базе или Redis), единый ограничитель на все реплики.
3. Нагрузочные испытания: число сделок и пользователей, время ответа, размер записи, поведение при конфликтах версий.
4. Шифрование и хранение секретов: ключи в хранилище секретов, ротация FILE_KEY и AUTH_SECRET, раздельные роли базы.
5. Контракты. Независимый аудит StepEscrow, тесты на основной сети только после аудита, описание обновляемости.
6. Юридическая часть. Оферта и политика обработки данных, порядок хранения персональных данных, взаимодействие с оператором платформы цифрового рубля.

## Известные ограничения сейчас

- При включенной тестовой сети работает один экземпляр API.
- Две одновременные правки одной записи платформы (например, меток прочтения чата) могут потерять одну из них.
- Счетчик запросов считается отдельно на каждом экземпляре.
- Сверка с ФНС в демо-режиме отключена.
- Пополнение работает как эмуляция.
