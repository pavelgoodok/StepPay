# StepPay — план разработки по этапам

Стек: монорепо (pnpm), TypeScript. Фронтенд — Next.js на **Vercel**, бэкенд (API + Postgres) — на **Railway**.
Деньги в копейках (целые числа), ядро сделок — чистые функции без зависимостей, чтобы легко переехать на платформу ЦБ.

| # | Этап | Результат | Статус |
|---|------|-----------|--------|
| 1 | Ядро сделок (`packages/engine`) | Состояния этапов, резерв/выплата/возврат, 3 режима, споры, автоприёмка, комиссия; тесты на инвариант «деньги не теряются» | ✅ |
| 2 | API (`apps/api`, Railway) | Fastify + Postgres, пользователи (демо-вход), кошелёк-эмулятор, CRUD сделок, шаблоны (ванная, кухня, электрика, сайт, свадьба), журнал операций, cron-тик автоприёмки | |
| 3 | Веб-приложение (`apps/web`, Vercel) | Mobile-first PWA по макетам: Сделки, Проекты (краудфандинг/гранты), «+» мастер создания, Кошелёк, Профиль; роли заказчик/исполнитель | |
| 4 | Приёмка и споры в UI | Сдача этапа с фото, «принял»/«спор», таймер автоприёмки, голосование спонсоров, панель приёмщика | |
| 5 | «Прогрессивный» слой | Живые обновления (SSE), анимация потока денег по этапам, тёмная тема, push, рейтинг исполнителя и публичная карточка, чеки самозанятого, AI-помощник: разбивка работ на этапы и критерии приёмки по описанию | |
| 6 | Демо-режим | Один клик «сценарий жюри»: ремонт 300 тыс. ₽ → переключение на краудфандинг за 30 секунд; сид-данные | |
| 7 | Деплой и релиз | Railway (API + БД), Vercel (web), переменные окружения, CI (typecheck + tests), ссылка на демо в заявку | |

Решения, которые принимаем по ходу: логин (демо-вход по роли vs. e-mail), хостинг файлов фото (S3-совместимое хранилище Railway), AI-провайдер для этапа 5.
